# README 编写规范

基于 HomeMediaViewer 项目 README 与代码一致性检查问题总结。

## 核心原则

**写代码实际做的，不写计划做的。**

---

## 检查清单

### 1. 功能声明必须有对应实现

| 错误示例 | 正确做法 |
|----------|----------|
| "支持用户管理" | 检查是否有实际的 CRUD 实现，而非空方法 |
| "自动提取元数据" | 检查返回值是否为实际数据，而非固定值/null |

**验证方法：** 搜索接口实现，确认不是 `return emptyList()` / `return null` / `return "not supported"`

---

### 2. 平台能力必须准确

| 错误示例 | 正确做法 |
|----------|----------|
| "所有平台可提供媒体服务" | 检查各平台是否有 HTTP Server 实现 |
| "鸿蒙支持完整功能" | 检查是否有对应模块（如 Service） |

**验证方法：** 列出各平台实际能力表，逐项确认

---

### 3. API 路径必须一致

| 错误示例 | 正确做法 |
|----------|----------|
| iOS 请求 `/thumbnail/{id}` | 服务端必须有对应路由 `/thumbnail/{id}` |

**验证方法：** 对比客户端请求路径和服务端路由定义

---

### 4. 权限声明必须真实

| 错误示例 | 正确做法 |
|----------|----------|
| "需要 READ_MEDIA 权限" | 检查 module.json5 / Info.plist 是否声明 |

**验证方法：** 检查实际权限配置文件，区分静态声明和动态请求

---

### 5. 文件路径必须存在

| 错误示例 | 正确做法 |
|----------|----------|
| 引用 `pad/` 目录 | 检查目录是否实际存在 |
| 引用 `hvigorw` 脚本 | 检查文件是否实际存在 |

**验证方法：** `ls` 或 `dir` 验证引用的文件/目录

---

### 6. 特性状态必须区分

| 状态 | 说明 | 文档标记 |
|------|------|----------|
| 已实现 | 有完整实现，可正常使用 | ✅ 已实现 |
| 接口定义 | 有接口但返回空值/stub | ⚠️ 接口已定义，待实现 |
| 计划中 | 尚未开始开发 | 📋 计划中 |
| 不支持 | 平台限制无法实现 | ❌ 不支持 |

---

### 7. 缩略图/媒体功能必须可验证

| 错误示例 | 正确做法 |
|----------|----------|
| "支持缩略图展示" | 检查 `getThumbnail()` 是否返回实际数据 |
| "视频帧自动生成" | 检查是否有视频帧提取实现 |

---

## 常见陷阱

### 陷阱一：接口有定义 = 功能已实现

```kotlin
// 接口定义
fun getUsers(): List<UserInfo> = emptyList()  // ❌ 这不是实现
```

### 陷阱二：客户端有请求 = 服务端有响应

```swift
// iOS 客户端
func getThumbnailUrl(id: String) -> String {
    "\(address)/thumbnail/\(id)"  // ❌ 服务端可能没有这个路由
}
```

### 陷阱三：权限被请求 = 权限已声明

```typescript
// 运行时请求
photoAccessHelper.requestPermissions(['ohos.permission.READ_MEDIA'])  // ❌ module.json5 可能未声明
```

## 文档编写流程

1. **先看代码** — 不要凭记忆写，打开文件确认
2. **验证实现** — 检查接口是否为空/stub
3. **对比路径** — 确认客户端/服务端 API 一致
4. **检查配置** — 确认权限/文件/目录存在
5. **标记状态** — 区分已实现/待实现/不支持
6. **交叉验证** — 让代码和文档互相印证
